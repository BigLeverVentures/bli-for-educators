# Coding for Shippers — Connected Exercise Path

[Curriculum](../curriculum.md) · Alpha release · [Evidence and limits](../educators/evaluation.md)

<h2>Begin with evidence and a useful result</h2>
<p>Begin with First Repository and Commit in a new harmless folder you own, or inspect an existing practice repository before adding anything. Keep a known working version. If the code is unfamiliar, use Codebase Explainer before you plan a change; it is a read-only orientation exercise.</p>
<h2>Before building for a pull request</h2>
<p>If you intend to propose a pull request, use First Pull Request’s setup first: establish the approved base and a separate branch, and preserve unrelated work. Build and test on that branch, then return for the finished diff review. A local-only tool needs no host account.</p>
<h2>Carry the work into the next step</h2>
<p>Use Build a Personal Tool for one repeated task. Define sample inputs and expected results before implementation. Run the normal, malformed and boundary cases, inspect the output, and correct a demonstrated problem. Then use First Pull Request when you have a host account and appropriate contribution access. Keep the branch focused and check the actual proposed diff.</p>
<p>If a technical step is confusing, <a href="../basics/basics-05.md">Work Through a Problem with AI</a> shows how to ask for one concrete next step. <a href="../basics/basics-09.md">Check Your Work and Choose What Comes Next</a> explains claimed versus actual actions; Git and runtime checks remain in the exercises.</p>
<h2>Use only the support you need</h2>
<p>A local tool and meaningful commit are useful even if hosting is unavailable. A pull request requires a host and contribution permissions; defer that exercise rather than claim you completed it. This path is a small practical introduction, not the full programming course.</p>
